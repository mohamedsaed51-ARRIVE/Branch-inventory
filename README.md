# جرد الفروع (Branch Inventory)

أدوات لتحليل جرد الفروع في ARRIVE: تجميع يومي من شيت الجرد + لوحة متابعة.

> المستودع عام (Public). **لا تُرفع هنا أي بيانات شحنات أو أسماء عملاء أو أرقام موبايل أو أسماء مناديب.** الكود والتوثيق فقط.

## المحتويات
| المسار | الوصف |
|---|---|
| `apps-script/Code.gs` | **ملف Apps Script الوحيد**: الإعدادات، الويب آب، تحديث التجميع، المحركان (ورقة لكل يوم / جدول واحد)، وبناء أوراق النظام الموحّد |
| `src/`, `index.html`, `package.json` | لوحة React + Vite |
| `docs/data-rules.md` | تعريفات القياس وقواعد مطابقة الأعمدة |
| `docs/sheet-improvements.md` | مقترحات تطوير شيت الجرد |

## Apps Script: ملف واحد
ضع `apps-script/Code.gs` **وحده** في مشروع الشيت (امسح أي ملف آخر فيه كود قديم). السبب: تكرار `const CFG` بين ملفين يوقف السكريبت بخطأ `Identifier 'CFG' has already been declared`، وتكرار اسم دالة (مثل `onOpen`) يمر بصمت ويغلب آخر ملف، وكلاهما سبّب مشاكل فعلية.

**أقسام الملف:** 1) الإعدادات `CFG` · 2) القائمة والمشغّلات · 3) الويب آب `doGet` · 4) نقطة التحديث `buildAuditSummary` · 5) المحرك أ: ورقة لكل يوم · 6) المحرك ب: جدول واحد · 7) `setupMerged` · 8) مواصفات الأوراق `SMG_SPEC` (مولّدة، آخر الملف).

**اختيار المحرك تلقائيًا:** إن كانت ورقة `الجرد` موجودة **وفيها بيانات** (رقم بوليصة في الصف 2) يعمل المحرك ب، وإلا المحرك أ. ورقة `الجرد` الفاضية لا تغيّر سلوك الشيت الحالي. يمكن فرضه من `CFG.MODE` (`perday` أو `unified`). المحركان يكتبان نفس المخرجات (`تجميع_الجرد` و`تجميع_شهري`) فاللوحة تعمل مع أيهما بلا تعديل.

| | المحرك أ (الشيت الحالي) | المحرك ب (الشيت الموحّد) |
|---|---|---|
| المصدر | ورقة لكل يوم (`1/11` و`31-10`) | ورقة `الجرد` بعمود «تاريخ الجرد» |
| مخرجات | تجميع_الجرد، تجميع_شهري، سجل_التجميع | + سجل_الشحنات، الحالات_المفتوحة، المفقودة، المتكررة، الأرشيف، سجل_الإجراءات، سجل_الأخطاء |
| إضافات | | استيراد ردود جماعي، ختم «بواسطة/آخر تعديل»، مفقود/متكرر/إغلاق، الجمعة إجازة |
| «تم التحديث» | من نص تعليق الأوديت | من عمود «نتيجة الأوديت» |
| ما تعرضه اللوحة | الكروت الشهرية والصحة والاتجاه والتغطية | + قسم «المتابعة» (مفتوحة/مغلقة/مفقودة/متكررة، زمن الاستجابة والإغلاق) وكارت «مغلقة» الشهري وتنبيهات المفقود |

### قسم «المتابعة» في اللوحة (المحرك ب فقط)
- المحرك ب يكتب ورقة `ملخص_المتابعة` (JSON) والويب آب يرجّعه في الحقل `follow`، واللوحة تعرضه: مؤشرات (مفتوحة، مغلقة، مفقودة، منتهية، متكررة، متوسط أيام استجابة الفرع والإغلاق، أقدم حالة مفتوحة)، ورسم وجدول لكل فرع، وتنبيهات ومقترحات للفروع التي فيها شحنات مفقودة.
- مع المحرك أ (ورقة لكل يوم) يظهر في اللوحة تنبيه بأن هذه المؤشرات تحتاج النظام الموحّد.
- **الخصوصية:** القوائم على مستوى الشحنة (المفقودة والمفتوحة والمتكررة بأرقام البوالص) **لا تُرسل افتراضيًا**؛ الويب آب يرسل أعدادًا فقط. لتفعيلها اضبط `CFG.EXPOSE_LISTS = true` (الحد `CFG.LIST_LIMIT` = 40 صفًا لكل قائمة). الرابط عام، فتفعيلها يعني أن أي صاحب رابط يرى أرقام البوالص.
- عمود جديد في `تجميع_شهري` (11): «مغلقة (تم الغلق)» لعدّاد الإغلاق الشهري. المحرك أ يكتب 10 أعمدة فقط واللوحة تتعامل مع الحالتين.

## التركيب
1. في الشيت: `إضافات ← Apps Script`، ملف واحد، والصق `Code.gs` كاملًا.
2. شغّل `buildAuditSummary` مرة ووافق على الصلاحيات.
3. من قائمة `جرد الفروع` اختر `تفعيل التحديث التلقائي` (كل ساعة، ومع المحرك أ عند إضافة ورقة، ومع المحرك ب عند التعديل).
4. المحرك أ: اختر `إعادة بناء كاملة` مرة بعد أي تعديل على الكود.

## بناء أوراق النظام الموحّد (`setupMerged`)
- شغّلها يدويًا (Run ← `setupMerged`) **على نسخة من الشيت أولًا**. تعرض اسم الملف وقائمة الأوراق وتطلب تأكيدك، وتعمل نسخة احتياطية في Drive، وتضيف أوراقًا جديدة فقط ولا تعدّل أي ورقة موجودة.
- ورقة `الجرد` تُنشأ بـ`SMG_GRID_ROWS` = 60,001 صف × 32 عمود (حوالي 1.9 مليون خلية). حد Google 10 ملايين خلية للملف كله، فقلّل القيمة (مثلًا 20001) لو الملف كبير.
- لا ترحّل بيانات الأيام القديمة إلى `الجرد`؛ تلك خطوة منفصلة.

## ملاحظات
- التحديث السريع (المحرك أ) يعيد قراءة أوراق آخر `RECENT_DAYS` (14) يومًا وأوراق الشهر الحالي والسابق، والأقدم يؤخذ من التجميع السابق.
- كل استدعاء للشيت يعيد المحاولة تلقائيًا (4 محاولات) عند مهلة `Service Spreadsheets timed out`.
- الأوراق المخفية تُقرأ وتظهر في السجل بكلمة «مخفية».
- **ما اختُبر:** كل الأجزاء اختُبرت بمحاكاة لـ`SpreadsheetApp` على بيانات ورقة `1/11` وبيانات تجريبية، ومقارنة بحساب مستقل. **لم يُشغَّل على Google Sheets الحقيقي** بعد.

## اللوحة (Vite + React) — بهوية ARRIVE
مبنية على نفس هيكل وهوية لوحة متابعة الشكاوى: ألوان ARRIVE الرسمية (V2.0) كمتغيرات CSS، وخطوط Cairo/Inter، وأيقونات Font Awesome، ورسوم Chart.js، ووضع داكن، وRTL.

الكروت **شهرية** (الشهر الحالي أو أي شهر من الفلتر) وكل كارت يذكر أساسه (حسب الأوديت / حسب الفرع) ونسبته من شحنات الشهر الفريدة. تحتاج ورقة `تجميع_شهري` من `Code.gs` المحدّث، وبدونها تعرض اللوحة تنبيهًا ولا تعرض أرقامًا تقديرية. مقترحات تطوير الشيت في `docs/sheet-improvements.md`.

ترتيب الأقسام: الهيدر ← شريط الحالة ← شريط التحكم (تحديث، إعادة تصفية، تصدير CSV، طباعة، ملء الشاشة) ← الفلاتر (فترة، فروع متعددة، بحث) ← المؤشرات الرئيسية ← صحة الفروع (4 مستويات) ← الاتجاهات والتوزيعات (Chart.js) ← مركز التنبيهات ← مركز الإجراءات ← رؤى الإدارة وأفضل/أضعف أداء ← وضع المقارنة (يومان) ← سجل الجرد اليومي بترقيم وتصدير.

- مستويات الصحة، والإجراءات المقترحة، والرؤى: قواعد آلية للعرض وليست قرارات معتمدة ولا ذكاءً اصطناعيًا. الحدود تُغيَّر من «إعدادات».
- «إعدادات» تحفظ رابط Apps Script والتحديث التلقائي والحدود في المتصفح (بدون إعادة نشر).
- `?demo=1` في الرابط أو زر «معاينة» يعرض **بيانات تجريبية غير حقيقية** مع شريط تنبيه.

### الربط بالبيانات
1. الويب آب جزء من `Code.gs` (القسم 3)، لا يحتاج ملفًا إضافيًا.
2. `Deploy ← New deployment ← Web app` (تنفيذ باسمك، الوصول: أي شخص) وانسخ رابط `/exec`.
3. إما من «إعدادات» داخل اللوحة (يُحفظ في متصفحك)، أو في Vercel: `Settings ← Environment Variables` أضف `VITE_DATA_URL` برابط `/exec` ثم أعد النشر. (Framework: Vite، Output: `dist`).
4. بدون رابط تعرض الصفحة رسالة إعداد فقط ولا تعرض أي بيانات.

### زر «تحديث»
- زر «تحديث» في اللوحة يطلب من الويب آب **إعادة التجميع** من أوراق الشيت (`?refresh=1`) ثم يعرض البيانات، فلا تحتاج فتح الشيت. قد يستغرق دقيقة أو أكثر، وتظهر رسالة انتظار.
- الحد الأدنى بين تحديثين 60 ثانية (`CFG.REFRESH_MIN_SECONDS` في `Code.gs`)، وإن كان تجميع آخر شغّالًا تُعرض آخر بيانات جاهزة مع تنبيه.
- التحديث التلقائي بالوقت (من «إعدادات») يقرأ البيانات فقط ولا يعيد التجميع.
- يحتاج `Code.gs` المحدّث + **New version** للنشر. بدونه يظل الزر يقرأ آخر تجميع فقط.
- أي شخص معه رابط الويب آب يقدر يطلب التحديث (محدود بالـ60 ثانية). للحماية الفعلية استخدم نشرًا خاصًا أو Vercel Password Protection.

### الخصوصية
- الريبو والموقع قد يكونان عامين. الويب آب يعرض **أرقامًا مجمّعة فقط** (الفرع، الشحنات، التحديث، التحصيل)، لكنها بيانات تشغيلية داخلية.
- `VITE_DATA_TOKEN` (مع خاصية `DATA_TOKEN` في Apps Script) يمنع الطلبات العشوائية فقط، وليس حماية حقيقية لأنه يظهر في كود الصفحة. للحماية الفعلية استخدم Vercel Password Protection أو نشرًا خاصًا.

### التشغيل محليًا
```bash
npm install
cp .env.example .env.local   # ثم عدّل VITE_DATA_URL
npm run dev
```
> جُرّبت اللوحة ببيانات اصطناعية للتأكد من البناء والعرض (سطح المكتب والموبايل) ولم تُجرَّب بعد على بيانات الشيت الحقيقية عبر Apps Script.
