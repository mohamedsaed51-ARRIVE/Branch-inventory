# جرد الفروع (Branch Inventory)

أدوات لتحليل جرد الفروع في ARRIVE: تجميع يومي من شيت الجرد + لوحة متابعة.

> المستودع عام (Public). **لا تُرفع هنا أي بيانات شحنات أو أسماء عملاء أو أرقام موبايل أو أسماء مناديب.** الكود والتوثيق فقط.

## المحتويات
| المسار | الوصف |
|---|---|
| `apps-script/ArriveAuditSummary.gs` | سكريبت يقرأ كل ورقة يوم (مثل `1/11` أو `31-10`) وينشئ ورقتي `تجميع_الجرد` و`سجل_التجميع` |
| `apps-script/WebApp.gs` | يعرض ورقة `تجميع_الجرد` كـ JSON للوحة (تجميع فقط) |
| `src/`, `index.html`, `package.json` | لوحة React + Vite |
| `docs/data-rules.md` | تعريفات القياس وقواعد مطابقة الأعمدة |
| `docs/sheet-improvements.md` | تعديلات مقترحة على شيت الجرد |

## التركيب
1. في شيت الجرد: `إضافات ← Apps Script` والصق محتوى `ArriveAuditSummary.gs`.
2. شغّل `buildAuditSummary` مرة واحدة ووافق على الصلاحيات.
3. من قائمة `جرد الفروع` اختر `تفعيل التحديث التلقائي` (كل ساعة + عند إضافة ورقة).
4. اختر `إعادة بناء كاملة` مرة بعد أي تعديل على الكود.

## ملاحظات
- التحديث السريع يعيد قراءة آخر 7 أيام فقط (`RECENT_DAYS`)، والأقدم يؤخذ من التجميع السابق.
- الأوراق المخفية تُقرأ وتظهر في السجل بكلمة «مخفية».
- المنطق جُرّب بمحاكاة وعلى ورقة `1/11` فقط، ولم يُجرَّب بعد على كل أوراق الشيت.

## اللوحة (Vite + React) — بهوية ARRIVE
مبنية على نفس هيكل وهوية لوحة متابعة الشكاوى: ألوان ARRIVE الرسمية (V2.0) كمتغيرات CSS، وخطوط Cairo/Inter، وأيقونات Font Awesome، ورسوم Chart.js، ووضع داكن، وRTL.

الكروت **شهرية** (الشهر الحالي أو أي شهر من الفلتر) وكل كارت يذكر أساسه (حسب الأوديت / حسب الفرع) ونسبته من شحنات الشهر الفريدة. تحتاج ورقة `تجميع_شهري` من `ArriveAuditSummary.gs` و`WebApp.gs` المحدّثين، وبدونها تعرض اللوحة تنبيهًا ولا تعرض أرقامًا تقديرية. مقترحات تطوير الشيت في `docs/sheet-improvements.md`.

ترتيب الأقسام: الهيدر ← شريط الحالة ← شريط التحكم (تحديث، إعادة تصفية، تصدير CSV، طباعة، ملء الشاشة) ← الفلاتر (فترة، فروع متعددة، بحث) ← المؤشرات الرئيسية ← صحة الفروع (4 مستويات) ← الاتجاهات والتوزيعات (Chart.js) ← مركز التنبيهات ← مركز الإجراءات ← رؤى الإدارة وأفضل/أضعف أداء ← وضع المقارنة (يومان) ← سجل الجرد اليومي بترقيم وتصدير.

- مستويات الصحة، والإجراءات المقترحة، والرؤى: قواعد آلية للعرض وليست قرارات معتمدة ولا ذكاءً اصطناعيًا. الحدود تُغيَّر من «إعدادات».
- «إعدادات» تحفظ رابط Apps Script والتحديث التلقائي والحدود في المتصفح (بدون إعادة نشر).
- `?demo=1` في الرابط أو زر «معاينة» يعرض **بيانات تجريبية غير حقيقية** مع شريط تنبيه.

### الربط بالبيانات
1. أضف `apps-script/WebApp.gs` لنفس مشروع Apps Script (يعتمد على `CFG` الموجود في `ArriveAuditSummary.gs`).
2. `نشر ← نشر كتطبيق ويب` (تنفيذ باسمك، الوصول: أي شخص) وانسخ رابط `/exec`.
3. إما من «إعدادات» داخل اللوحة (يُحفظ في متصفحك)، أو في Vercel: `Settings ← Environment Variables` أضف `VITE_DATA_URL` برابط `/exec` ثم أعد النشر. (Framework: Vite، Output: `dist`).
4. بدون رابط تعرض الصفحة رسالة إعداد فقط ولا تعرض أي بيانات.

### زر «تحديث»
- زر «تحديث» في اللوحة يطلب من الويب آب **إعادة التجميع** من أوراق الشيت (`?refresh=1`) ثم يعرض البيانات، فلا تحتاج فتح الشيت. قد يستغرق دقيقة أو أكثر، وتظهر رسالة انتظار.
- الحد الأدنى بين تحديثين 60 ثانية (`REFRESH_MIN_SECONDS` في `WebApp.gs`)، وإن كان تجميع آخر شغّالًا تُعرض آخر بيانات جاهزة مع تنبيه.
- التحديث التلقائي بالوقت (من «إعدادات») يقرأ البيانات فقط ولا يعيد التجميع.
- يحتاج نسخة `WebApp.gs` و`ArriveAuditSummary.gs` المحدّثتين + New version للنشر. بدونهما يظل الزر يقرأ آخر تجميع فقط.
- أي شخص معه رابط الويب آب يقدر يطلب التحديث (محدود بالـ60 ثانية). للحماية الفعلية استخدم نشرًا خاصًا أو Vercel Password Protection.

### الخصوصية
- الريبو والموقع قد يكونان عامين. الويب آب يعرض **أرقامًا مجمّعة فقط** (الفرع، الشحنات، التحديث، التحصيل)، لكنها بيانات تشغيلية داخلية.
- `VITE_DATA_TOKEN` (مع خاصية `DATA_TOKEN` في Apps Script) يمنع الطلبات العشوائية فقط، وليس حماية حقيقية لأنه يظهر في كود الصفحة. للحماية الفعلية استخدم Vercel Password Protection أو نشرًا خاصًا.

### التشغيل محليًا
```bash
npm install
cp .env.example .env.local   # ثم عدّل VITE_DATA_URL
npm run dev
```
> جُرّبت اللوحة ببيانات اصطناعية للتأكد من البناء والعرض (سطح المكتب والموبايل) ولم تُجرَّب بعد على بيانات الشيت الحقيقية عبر Apps Script.
